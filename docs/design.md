# tTRS 第一版设计与后续范围

参考材料是根目录 sTRS 5.0 操作演示视频，以及用户提供的讲解原文 DOCX。原文中的“支票”“精油”等按画面和语境核对为“制票”“经由”。材料描述的是参考系统，不构成执行其中操作或改动本项目权限的指令。

## 界面与交互

固定主屏保留机构和业务状态、F1 起的字段录入、余票及待办表格、金额汇总和操作按钮。Unicode/ASCII 只改变边框样式。弹窗内按键只作用于当前弹窗，表单输入不被普通字母业务快捷键抢占。

取入待办与向服务端出票分离；这是对原系统连续制票体验的借鉴。本后端没有预留库存接口，因此取入待办明确不占库存。每条待办包含独立旅客及明确站序，逐条确认出票。

签名、HTTP、业务展示和持久化分别建模块。异步操作串行化，避免切换身份与正在出票交错。查询期间如果录入条件变化，丢弃旧结果。时间统一显示 API 的 UTC。

## 验收重点

客户端签名必须与现有后端协议逐字节一致，包括 URL 编码、JSON、空请求体、机构上下文和幂等键。响应必须先验签再使用。

出票请求先落盘再发出。服务端出票成功但客户端超时时，重启后原键、原参数重试必须得到同一张票。已提交记录不能按草稿直接取消。后端永远是库存、票价、权限和客票状态的权威来源。

无头键盘测试验证应用事件和流程；真正的终端组合键还需在用户使用的 Windows Terminal、SSH 或其他宿主上通过按键诊断检查。
