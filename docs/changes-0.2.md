# tTRS 0.2 更新

## 连续录入与快捷操作

- Ctrl+Y 进入往返录入：取入首程后交换发到站，取入返程后返回普通模式。
- Ctrl+L 进入联程录入：取入每一程后，下一程发站锁定为上一程到站；F4 选择下一程到站。
- 后续行程不得早于上一程到达时间；支持跨午夜。客户端同时检查返回结果，避免秒级查询精度放过更早的毫秒时刻。
- F6 可从菜单切换模式，Alt+S 返回普通售票。取消未提交待办会重置连续录入状态。
- Alt+M 修改未提交待办的旅客姓名或证件库 ID，已提交订单保持原参数。
- 日期支持完整日期、日简码及 +N：例如 30 表示从当前 UTC 日期起最近一个 30 日，+1 表示 UTC 明天。实际查询日期显示在余票表标题；出生日期仍只接受完整日期。

连续录入只是提高录入效率，各程仍按原后端分别报价和出票，不代表联程优惠、通票、换乘保障或整体事务。

## 失败与恢复

网络中断、验签失败和服务端 5xx 后保留“待确认”。已验签的 4xx 响应显示“后端拒绝”，并保存最近错误。后端拒绝仅说明这次请求被拒绝，不推断曾经的网络异常一定没有产生客票。

重试统一保留原幂等键与原参数，发送前先将状态持久化为待确认；只有收到可信成功响应才标记已出票。已确认出票记录不会被迟到的错误降级。

修复多张待办提交一张后，表格焦点落到另一张票的问题。焦点现在按订单 ID 保持，失败后重试仍指向原订单。旧 SQLite 订单库自动补充错误字段，保留已有记录。

0.2 中切换服务或出票方前提示未提交待办会被丢弃；0.3 起已改为持久化保留，详见 [0.3 更新说明](changes-0.3.md)。重新连接同一服务及出票方会恢复待办。已提交记录继续按服务和出票方隔离。

## 配置

错误类型、超时范围、未知动作和空键位在启动前检查；Debian 支持 XDG_STATE_HOME。订单创建时间相同时，按实际插入顺序显示。
