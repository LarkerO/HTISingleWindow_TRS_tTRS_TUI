# 原后端对接验证记录

本次验证使用当前 backend/ 的真实 ThinkPHP HTTP 路由、HMAC-SM3 认证、MariaDB 库存及客票服务，同时以 Textual 的无头键盘驱动操作 tTRS 界面。未使用 DemoServer 或 httpx.MockTransport。

## 已通过的链路

1. 出票方身份认证与响应验签。
2. 真实车站目录查询。
3. 区间报价和可售库存查询。
4. 临时旅客证件登记。
5. 实际 TUI 连接原后端，并选择该旅客证件。
6. TUI 查询班次、保存待办、出票并显示电子票面。
7. 同一幂等键与原参数重试，返回同一票号，库存只减少一次。
8. 真实客票查询。
9. TUI 办理整票退票。
10. 重复退票仍为 RFND，库存不重复增加。

独立测试班次的库存实测为 10 → 9 → 10。出票使用了实际后端返回的报价版本和证件库 ID。

## 隔离和清理

复用后端 tests/passenger-fixture.php 创建随机后缀的测试机构、2099 年未来班次和临时旅客。未用现有业务班次出票。验证结束后执行 fixture cleanup，再检查测试班次、客票、出票方、运营方及证件记录数量均为 0；临时 PHP 服务已停止。正常请求日志及短期防重放记录遵循原后端现有机制。

该检查共 11 个验证点通过。每次运行的详细报告写入忽略目录 .local/live-<随机后缀>/report.json，不随仓库上传。

## 复现

在配置了原 PHP 后端及数据库的 Debian 开发环境中（后端位于同级 backend/ 或由 TTRS_BACKEND_DIR 指定）：

```bash
uv run --locked --extra dev python tools/live_backend.py
```

该工具会创建临时测试记录、启动独立端口服务并在 finally 中清理和校验。它要求本地 backend/ 数据库配置有效；不会输出 API 密钥。运行失败时也会尝试清理，最终报告记录清理结果。

## 验证范围

这是核心售票链路对接验证，不代表扩展业务全部存在。原后端尚未提供的指定席位、真实支付、改签、通票签证、实体制票机和交班结算仍不可办理。

实际使用时启动 tTRS 不加 --demo，通过 Ctrl+O 连接原后端地址并输入相应密钥。--demo 是独立的本地演示模式，不会连接原后端。

本次无头键盘驱动验证了实际界面与后端的衔接；不同终端对物理快捷键的截获仍以 --keys 诊断结果为准。
