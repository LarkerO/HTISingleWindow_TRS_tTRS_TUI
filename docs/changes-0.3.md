# tTRS 0.3 更新

## 未提交待办跨重启保存

从 0.3 起，取入待办即写入本地 SQLite。编辑旅客和取消待办也立即保存。退出程序、切换服务或出票方不会丢弃待办；重新连接相同服务和出票方后恢复。演示默认仍使用内存数据库，退出即清空。

恢复的是已取入的票务待办；连接后录入模式回到普通售票，下一程的输入栏不会自动恢复。待办中的余票和金额是原查询快照，不预留库存，也不保证重启后报价仍有效。

点击确认出票时，在一个 SQLite 事务中读取当前版本、生成并保存幂等键，然后删除原草稿。中途失败会整体回滚；两个窗口无法把同一待办转成两张独立订单。已被其他窗口修改或提交的待办会要求重新选择，防止用陈旧资料出票。

旧订单库自动新增待办表，已有订单、票号与幂等键保持不变。

## 可读电子票面

出票或查看详情时显示对齐的线框票面：票号、PNR、旅客、票价、出票方、出票时间、乘车区间、车次、发到时刻和站序。时刻为 UTC；服务端未提供的内容显示未提供，不生成虚构的席位。

- F7：查看已验签响应中的原始客票数据。
- F8：选择完整路径，导出 TXT 或 JSON。
- Esc：返回。

TXT 票面默认遮蔽证件号码；JSON 包含完整后台数据，可能包括证件快照。导出由用户主动触发，默认在本地数据目录下的 receipts/，也可以指定其他路径。已有文件不会被覆盖。票面核对单不是实体纸票或付款凭证，状态可能随之后的退票等操作变化。

## 小终端布局

修复 80×24 下长票面、原始数据、多字段表单把按钮挤出可见区域的问题。长内容在弹窗内部滚动，按钮保持可见。保留 Unicode 和 ASCII 两种外观。

## 验证

覆盖待办重启恢复、版本冲突、原子转单回滚、陈旧窗口防重复提交、中文票面对齐、证件遮蔽、导出不覆盖、80×24 和 120×36 下的查看及导出流程。
